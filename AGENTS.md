# AGENTS.md

Guidance for AI coding agents working in this repository.

## What this repo is

Source of https://gujiakai.top — a bilingual weekly blog (Chinese default,
English secondary) on Next.js 16 App Router with React 19, Tailwind CSS 4,
and MUI 9. Posts are local Markdown files rendered through a unified
remark/rehype pipeline. Comments live in Supabase, gated by Cloudflare
Turnstile, with nodemailer email notifications. Deploys self-hosted via
Docker (`output: 'standalone'`); docker-compose binds 127.0.0.1:3802 and
mounts `./posts` as a volume. Theme forked from simple-is-awesome/simple.

## File map

- `app/[lang]/` — pages: home + `/page/[page]`, `/tag/[tag]`, `/archive`,
  `/about`, posts at `/[year]/[month]/[slug]` (fully static via
  `generateStaticParams`)
- `app/api/comInsert|comSelect/route.ts` — Supabase comment endpoints
- `app/llms.txt/route.ts`, `app/robots.ts`, `app/sitemap.ts` — SEO endpoints
- `proxy.ts` — Next proxy (middleware): zh URLs are prefix-less (internally
  rewritten to `/zh/...`), `/en/...` passes through, `/zh/...` redirects to
  the bare path; skips `/api`, `_next`, dotted paths, `/index.xml`
- `lib/posts/index.ts` — reads `posts/<locale>/*.md(x)`, gray-matter
  frontmatter, remark→rehype pipeline (gfm, gemoji, raw, slug, local
  `enhancePostHtml` plugin, autolink-headings, prism)
- `lib/renderComment.ts` + `.test.ts` — sanitized comment Markdown rendering
- `lib/dictionaries/`, `lib/i18n-config.ts` — UI strings, locale helpers
- `posts/zh/`, `posts/en/` — content; frontmatter fields: `title`, `date`,
  `slug`, `tags`, `summary`, `draft`, `showtoc`, `audio`
- `scripts/generate-rss.mjs` — postbuild Atom feeds → `public/index.xml`,
  `public/en/index.xml` (committed but regenerated on every build; don't
  hand-edit)
- `components/` — one directory per component (Header, Footer,
  ArticleLayout, ArticleToc, Comment*, APlayer, PostCard, ...)
- `next.config.mjs` — standalone output, security headers incl. CSP,
  bundle analyzer, `image.gujiakai.top` remote images
- `pnpm-workspace.yaml` — NOT a monorepo: pnpm build allowlist + security
  version overrides (js-yaml, postcss, undici)
- `.github/workflows/release.yml` — semantic-release on push to main
- `docs/CHANGELOG.md` — generated by semantic-release; never edit by hand

## Commands

pnpm only (`packageManager` pins pnpm@11.5.2; Node >=22.13, `.node-version`
is 24.16.0). All from package.json scripts:

- `pnpm dev` — dev server (Turbopack)
- `pnpm build` — production build; `postbuild` regenerates the Atom feeds
- `pnpm start` — serve the production build
- `pnpm test` — Vitest, runs `lib/**/*.test.ts` in node environment
- `pnpm lint` — ESLint with `--fix`
- `pnpm clean` / `pnpm clear` — `rm -rf .next` (POSIX shell only)
- `ANALYZE=true pnpm build` — bundle analyzer

## Architecture & conventions

- Public URLs never carry a `zh` prefix; `proxy.ts` maps them onto the
  `app/[lang]` tree. New non-page routes must be added to its skip list.
- The RSS script re-implements a trimmed copy of the `lib/posts` markdown
  pipeline in plain JS (no gemoji, rehype-raw, or enhancePostHtml) — keep
  the two consistent when changing post rendering.
- Comment HTML goes through rehype-sanitize; the `hardenLinks` plugin runs
  before sanitize on purpose (sanitize validates the injected attributes).
- ESLint enforces: tab indentation, single quotes, no semicolons, and LF
  line endings (`linebreak-style: unix`) — mind this on Windows.
- Conventional Commits are required: semantic-release derives releases from
  commit messages; simple-git-hooks pre-commit runs lint-staged (eslint).
- Env vars (public): NEXT_PUBLIC_ SITE_URL, SITE_TITLE, SITE_DESCRIPTION,
  KEYWORDS, FOOTER, POSTS_PERPAGE, SHOW_COMMENT, GITHUB_REPO, SUPABASE_URL,
  SUPABASE_ANON_KEY, CLOUDFLARE_TURNSTILE_SITE_KEY. Server-only:
  CLOUDFLARE_TURNSTILE_SECRET_KEY, EMAIL_HOST/PORT/SECURE/USERNAME/PASSWORD,
  MASTER_EMAIL.

## Validation

- `pnpm lint` and `pnpm test` (single suite: `lib/renderComment.test.ts`).
- `pnpm build` statically generates every post page, so bad frontmatter or a
  broken pipeline fails the build.
- There is no CI test/build gate — the only workflow is the release job —
  so validate locally before pushing to main.

## Gotchas

- **Windows filename trap (do not "fix")**: two tracked posts contain a
  literal `?`, invalid in Windows filenames:
  `posts/zh/AI情感伴侣选择谁?-21.md` and `posts/zh/小红书真的能脱单?-19.md`.
  Windows cannot check them out, so this clone marks both `skip-worktree`
  (`git ls-files -v posts/zh` shows `S` entries) and they look absent on
  disk. Never stage or commit their deletion, never rename them, and leave
  the skip-worktree bits alone. Edit those two files only from a
  non-Windows checkout.
- `pnpm-workspace.yaml` is not a workspace definition — deleting it drops
  the security overrides pinned there.
- `package.json` version stays `0.0.1-development`; semantic-release owns
  real version numbers (`npmPublish: false`) and commits the changelog.
- RSS generation is deliberately a postbuild step, not a render-time side
  effect; `.npmrc` sets `enable-pre-post-scripts=true`, so `postbuild` only
  fires when building via pnpm.
